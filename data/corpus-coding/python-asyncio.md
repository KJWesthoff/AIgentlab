# Python asyncio: coroutines, tasks, and the event loop

Python asyncio provides cooperative concurrency on a single thread using an event loop. A coroutine is defined with `async def` and does nothing until awaited or scheduled. Calling a coroutine function returns a coroutine object; execution only starts when you `await` it or wrap it in a task with `asyncio.create_task()`. The entry point of an asyncio program is `asyncio.run(main())`, which creates the event loop, runs the coroutine to completion, and closes the loop.

The difference between `await coroutine()` and `asyncio.create_task(coroutine())` is sequencing versus concurrency. Plain `await` runs the coroutine to completion before the next line executes, so awaiting three coroutines in a row is sequential. `asyncio.create_task()` schedules the coroutine on the event loop immediately and returns a Task handle, so multiple tasks run concurrently and you await the handles later to collect results.

To run many coroutines concurrently and gather their results, use `asyncio.gather(*coros)`, which returns results in the same order as the arguments. With `return_exceptions=True`, gather returns exceptions as values instead of raising the first one, so one failed task does not cancel the rest. Python 3.11 added `asyncio.TaskGroup`, an async context manager that is generally preferred: it cancels all sibling tasks when one fails and raises the failures as an ExceptionGroup.

Blocking calls freeze the entire event loop because asyncio concurrency is cooperative: nothing else runs until the current coroutine yields at an `await`. Never call `time.sleep()`, blocking `requests` HTTP calls, or heavy CPU work directly inside a coroutine. Use `await asyncio.sleep()` for delays, an async client such as `httpx.AsyncClient` or `aiohttp` for HTTP, and `await asyncio.to_thread(blocking_fn, *args)` to push blocking or CPU-bound work onto a worker thread.

Timeouts and cancellation: `asyncio.wait_for(coro, timeout=5)` raises `asyncio.TimeoutError` (an alias of `TimeoutError` since 3.11) if the awaitable does not finish in time, and cancels it. Python 3.11 also added `asyncio.timeout()` as an async context manager. Cancellation works by raising `asyncio.CancelledError` inside the task at its next await point; catch it only to clean up, and re-raise it, otherwise the task swallows the cancellation.

A common asyncio pitfall is forgetting to keep a reference to a task: the event loop holds only a weak reference, so a fire-and-forget `asyncio.create_task()` result can be garbage collected mid-flight. Store tasks in a collection or use a TaskGroup. Another pitfall is mixing sync and async code paths: an `async def` function can call sync functions freely, but sync code cannot await; bridging from sync into async requires `asyncio.run()` (fails if a loop is already running in that thread).
