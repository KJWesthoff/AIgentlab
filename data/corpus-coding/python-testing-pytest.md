# Python testing with pytest

pytest discovers tests automatically: files named `test_*.py` or `*_test.py`, functions prefixed `test_`, and classes prefixed `Test` without an `__init__`. Assertions are plain `assert` statements — pytest rewrites them to show the values of subexpressions on failure, so no assertEqual-style methods are needed. Run the suite with `pytest`, a single file with `pytest tests/test_api.py`, a single test with `pytest tests/test_api.py::test_login`, and by keyword with `pytest -k "login and not slow"`.

Fixtures provide setup and teardown through dependency injection: declare `@pytest.fixture` on a function, and any test naming it as a parameter receives its return value. Teardown is written with `yield` — code after the yield runs when the test finishes. The `scope` argument ("function" by default, or "class", "module", "session") controls how often the fixture is rebuilt. Fixtures placed in a `conftest.py` are available to all tests in that directory tree without imports.

Expected failures and exceptions: `with pytest.raises(ValueError, match="invalid"):` asserts the block raises and optionally that the message matches a regex pattern. `pytest.raises` gives access to the exception via `excinfo.value`. Mark tests with `@pytest.mark.skip(reason=...)`, `@pytest.mark.skipif(condition, reason=...)`, or `@pytest.mark.xfail` for known failures; custom marks like `@pytest.mark.slow` are registered in config and selected with `-m slow`.

Parametrize turns one test into many cases: `@pytest.mark.parametrize("raw,expected", [("1", 1), ("-3", -3), ("07", 7)])` runs the test once per tuple, each shown as a separate test id. Stacked parametrize decorators produce the cross product. This is preferred over a for-loop inside the test, because each case reports pass/fail independently and failures do not mask later cases.

Built-in fixtures cover common needs: `tmp_path` yields a fresh `pathlib.Path` temporary directory per test; `monkeypatch` sets and automatically restores attributes and environment variables (`monkeypatch.setenv("API_KEY", "x")`, `monkeypatch.setattr(mod, "fn", fake)`); `capsys` captures stdout/stderr for asserting printed output. For async tests, pytest-asyncio runs `async def` test functions; with `asyncio_mode = "auto"` in config no per-test marker is needed.

Test doubles: `unittest.mock.patch` or monkeypatch replaces collaborators at their point of use — patch where the name is looked up (`patch("app.service.http_get")`), not where it is defined. Overuse of mocks couples tests to implementation details; prefer designing seams (dependency injection of a provider/client object) so tests can pass a scripted stub and assert observable behavior rather than call sequences. `pytest --cov=mypkg` (pytest-cov) reports line coverage.
