# TypeScript and JavaScript async: promises, await, and concurrency

A Promise represents a value that will be available later; it is in one of three states: pending, fulfilled, or rejected. `async` functions always return a Promise, and `await` pauses the function (not the thread) until the promise settles, returning the fulfilled value or throwing the rejection. In TypeScript an async function's return type is `Promise<T>`; `await` unwraps it to `T`. Rejections inside async functions are caught with ordinary try/catch around the await.

Sequential versus parallel awaits is the most common async performance mistake: `const a = await fetchA(); const b = await fetchB();` runs the calls one after another, while starting both promises first (`const pa = fetchA(); const pb = fetchB(); const [a, b] = await Promise.all([pa, pb]);`) runs them concurrently. `Promise.all` rejects as soon as any input rejects; `Promise.allSettled` always waits for every input and returns `{status, value|reason}` records, the right choice when partial failure is acceptable.

`Promise.race` settles with the first promise to settle (fulfilled or rejected), useful for timeouts; `Promise.any` fulfills with the first fulfillment and only rejects (with AggregateError) if all inputs reject. A timeout wrapper combines race with a timer: race the work against `new Promise((_, reject) => setTimeout(() => reject(new Error("timeout")), ms))`, or use `AbortController` and pass its `signal` to fetch, then call `controller.abort()` in the timer for a cancellation that the request actually observes.

Unhandled rejections come from promises whose rejection no handler consumes — commonly a fire-and-forget `doAsyncThing()` call without await or `.catch()`. In Node.js unhandled rejections terminate the process by default. Every created promise should be awaited, returned, or given a `.catch`; when intentionally not awaiting, add `void doAsyncThing().catch(log)` to make the choice explicit. The `@typescript-eslint/no-floating-promises` lint rule catches these mechanically.

In a `catch` block, TypeScript types the caught value as `unknown` (with `useUnknownInCatchVariables` under strict mode), because JavaScript can throw anything, not just Error. Narrow before use: `if (err instanceof Error) log(err.message)`. When rethrowing with added context, wrap with `new Error("context", { cause: err })` so the original error and stack are preserved on the `cause` property.

Async iteration: `for await (const chunk of stream)` consumes async iterables such as Node streams and paginated APIs; an `async function*` defines an async generator that yields values over time. Note that `Array.prototype.forEach` ignores returned promises — `items.forEach(async item => ...)` does not wait and hides errors; use `for...of` with await for sequential processing or `await Promise.all(items.map(async item => ...))` for parallel processing.
