# TypeScript project tooling: npm, linting, formatting, and testing

npm dependency management: `dependencies` are packages the code needs at runtime; `devDependencies` (installed with `npm i -D`) are build/test/lint tools not shipped to production. `package-lock.json` pins the exact resolved versions of the entire tree and belongs in version control; `npm ci` installs exactly from the lock file (fast, reproducible, right for CI), while `npm install` may update the lock. Semver ranges: `^1.2.3` allows minor and patch updates, `~1.2.3` allows patch only, and an exact version pins completely.

npm scripts in package.json are the conventional task runner: `"scripts": { "build": "tsc", "test": "vitest run", "lint": "eslint ." }`, executed with `npm run build` (`npm test` and `npm start` need no `run`). Scripts run with `node_modules/.bin` on PATH, so locally installed CLIs are invoked without global installs; `npx <tool>` does the same for one-off invocations. Pre/post hooks (`pretest`) run automatically around the named script.

ESLint with typescript-eslint lints TypeScript for correctness issues that the compiler does not flag: floating promises, unused variables, unsafe `any` flows, and await-in-loop patterns. Modern ESLint uses flat config (`eslint.config.js`) and the `typescript-eslint` package's recommended presets; type-aware rules need a `parserOptions.projectService` (or `project`) pointing at the tsconfig. Formatting is delegated to Prettier — run it separately rather than through ESLint rules, and disable stylistic ESLint rules that conflict via `eslint-config-prettier`. Biome is a fast single-tool alternative covering both linting and formatting.

Vitest is the common modern test runner for TypeScript: test files named `*.test.ts`, `describe`/`it`/`expect` API compatible with Jest, native ESM and TypeScript support without transform configuration, watch mode by default (`vitest run` for single-pass CI), and built-in coverage via `--coverage`. Mocking uses `vi.fn()` for function stubs, `vi.mock("./module")` for module replacement, and `vi.useFakeTimers()` for time control. Node's built-in `node:test` runner is a zero-dependency alternative for small projects.

Monorepos use npm/pnpm/yarn workspaces: a root package.json declares `"workspaces": ["packages/*"]`, dependencies between packages are linked locally, and pnpm is popular for its strict, disk-efficient node_modules layout. TypeScript project references (`"references"` in tsconfig plus `composite: true`) let `tsc --build` type-check packages incrementally in dependency order. Shared config (tsconfig bases, eslint presets) typically lives in a dedicated internal package.

Debugging Node and TypeScript: `node --inspect` (or `--inspect-brk` to pause at start) opens a debugger port that VS Code and Chrome DevTools attach to; with source maps enabled breakpoints map back to `.ts` sources. In VS Code, a launch.json with `"type": "node"` and `"runtimeArgs": ["--import", "tsx"]` debugs TypeScript directly. `console.log` debugging aside, `util.inspect(obj, { depth: null })` prints deep structures, and `NODE_OPTIONS=--stack-trace-limit=50` lengthens truncated stacks.
